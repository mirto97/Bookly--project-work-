# Backlog Backend – 25/03/2026

## Cosa abbiamo fatto oggi

### Prefisso /bookly/ agli endpoint
Tutti i controller REST sono stati aggiornati aggiungendo `/bookly/` davanti al path base.
Prima era `/api/activities`, adesso è `/bookly/api/activities`. Stessa cosa per tutti gli altri.
Questo serve per distinguere le chiamate dell'app Bookly da eventuali altri endpoint in futuro.

### ActivityAPI – nuovi endpoint
Il controller delle attività è stato riscritto. Sono stati aggiunti:

- `GET /bookly/api/activities/approved` — restituisce solo le attività approvate, quelle visibili agli utenti
- `GET /bookly/api/activities/pending` — restituisce le attività in attesa di approvazione, visibile solo all'admin
- `PATCH /bookly/api/activities/{id}/status?status=` — permette all'admin di cambiare lo status di un'attività (APPROVED, PENDING, BANNED, REFUSED)

Il vecchio `GET /api/activities` e il `POST /api/activities` sono stati rimossi e sostituiti da questi.

### ActivityService – nuovi metodi
Aggiunti i metodi corrispondenti ai nuovi endpoint:
- `getAllActivityPending()` — prende le attività con status PENDING
- `updateStatus(id, newStatus)` — aggiorna lo status e salva con JPA

### ActivityRepository – nuova query
Aggiunto `findByStatus(ActivityStatus status)` per filtrare le attività per status direttamente nel database.

### Rimosso DataSeeder.java
Il file che caricava dati di test all'avvio è stato eliminato. Non serviva più.

### Fix ActivityDTO
Il campo `registrationDate` aveva `@NotBlank` che non si può usare su `LocalDateTime`.
Sostituito con `@NotNull`.

### File di test aggiunti
Sono stati aggiunti due file JS nella cartella test:
- `OkTestsApis.js` — test per i casi corretti
- `ErrorTestsApis.js` — test per i casi di errore

### Fix bug ActivityService – findByActivityId
Il metodo `getAppointmentsByActivityId()` in `ActivityService` chiamava `bookingRepository.findByActivityId()` che non esiste.
Il metodo corretto nel repository è `findByServiceActivityId()` perché JPA deve navigare la relazione booking → service → activity per trovare i booking di un'attività.
Il bug non era stato scoperto dal collega perché non aveva mai fatto un clean build — le classi vecchie in `target/` nascondevano l'errore.
